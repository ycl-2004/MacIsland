# Shelf（用户称 Shift）完整评估

日期：2026-10-17。源码基线：`578a61ec`。本轮是评估，不修改产品行为、不替换安装版。

## 结论

Shelf 适合成为**跨应用文件交接的临时中转站**。已有能力不少，当前更值得投入的是接收可靠性、即时反馈、快捷入口和内容整理。没有实际使用日志，不能断言使用率低的原因；下文对使用频次的解释是待验证的产品假设。

普通本地文件的解析没有测到明显主线程冻结；慢来源整批等待、200 项视图构建与长文本起拖预览则有明确优化空间。现有 Shelf 回归 **26/26 通过**，本轮独立评估探针 **5/5 通过**。测试通过说明探针执行和既有用例成立，不代表下面列出的产品问题不存在。

本仓库没有名为 Shift 的独立暂存模块；按用户描述的拖拽功能，将评估对象解释为 Shelf。原始需求逐项保留：①检查拖拽卡顿；②梳理常用 Feature；③排查当前问题；④提出使其值得常驻、提高使用频次的方案。

## 1. 证据与范围

- 阅读入口路由、卡片、拖入/拖出、多选、预览/分享、持久化、临时文件、缩略图、设置与相关测试。
- SwiftUI + AppKit 原生 macOS 应用；产品 target 最低 macOS 14.6、Swift 5 语言模式。测试环境为 macOS 27.0.1 / Xcode 27.1，Debug 隔离宿主。
- 当前实测结果和可复跑探针见 [证据目录](audit/2026-10-17-shelf-assessment/README.md)。历史审计仅用来避免重复报告已修复问题，不代替本轮测试。
- 没有在用户安装版上执行真实 Finder → Shelf → 浏览器拖拽、AirDrop 发送、多屏或睡眠唤醒。组件耗时、主线程心跳与真实显示帧率分别解释，不能互相代替。

## 2. 拖拽链路与性能判断

路径：拖入刘海 → 自动展开/切页 → 接收 provider → 顺序解析 → 整批加入 → 加载可见缩略图 → 选择 → 同步构造拖拽预览 → AppKit 拖出 → 接收方确认操作 → 可选移除引用。

### 已经做对的部分

- 旧的主线程 5 秒 semaphore 等待已被移除；正常文件路径使用 `cachedPath`。
- 文件元数据/书签解析主要异步执行；持久化在 utility 队列上合并写入。
- 缩略图最多同时生成 2 个，LRU 最多 48 项 / 8 MiB；仅可见卡片请求图片。
- 拖拽预览在起拖时生成一次；框选集合不变时不重复发布状态。
- 拖出和框选期间抑制刘海自动关闭，避免源视图被销毁。
- 普通 Finder 文件只保存引用；剪贴板、拖出、预览、分享通过 lease 保护临时副本。

依据：[拖出实现](../DynamicIsland/components/Shelf/Views/ShelfItemView.swift:366)、[缩略图服务](../DynamicIsland/components/Shelf/Services/ThumbnailService.swift:31)、[关闭抑制](../DynamicIsland/ContentView.swift:1994)。

### 需要区分的四类延迟

| 环节 | 代码事实 | 判断 / 下一步 |
| --- | --- | --- |
| 拖入后没有内容 | provider 顺序处理，整批完成后才发布；导入过程中没有 loading/progress | 用户能移动鼠标也会觉得“卡了”。先即时显示接收数量和占位卡，再考虑有界并发与逐项完成 |

| 右键/旧书签/远程盘 | 右键同步查询目录、可打开应用与图标；无缓存路径时仍同步解析书签 | 是主线程 I/O 风险；没有测量 NAS 断连，不能给出实际冻结时长。可缓存/异步准备菜单，移除起拖同步兜底 |

### 本轮测量

| 场景 | 观察 | 能得出的结论 |
| --- | --- | --- |
| 1 / 10 / 50 个本地小文件，经真实 NSItemProvider 导入 | 两轮分别约 69–83 / 42–47 / 189–231 ms | 1 项在各轮最先执行，含首次访问成本；不是“文件越多越快”。不包含刘海动画和完整卡片显示 |
| 导入时 5 ms MainActor 心跳 | 最大间隔约 6.1–6.4 ms | 该样本未见明显主线程冻结；不是帧率指标，也不覆盖 NAS/云文件 |
| 快项 + 人工延迟 600 ms 的项，再排一批 | 150 ms 时仍为 0 项、无反馈；约 605–612 ms 首批两项才出现，下一批约 607–614 ms | 已复现整批及后批等待。600 ms 是主动注入的延迟，不是真实应用来源的典型值 |
| 起拖预览，40 字符 | 首次 14–22 ms，后续约 0.7–2.7 ms | 首次渲染成本值得关注，普通热态文本本身较轻 |
| 起拖预览，1 MiB ASCII 文本 | 两轮共六次约 29–39 ms | 同步主线程段超过单帧预算，有起拖顿一下的风险；并非秒级冻结。4 KiB / 64 KiB 样本约 2–4 ms |
| 真实 ShelfView，1 / 50 / 200 个短文本卡片 | 新建宿主与首次同步布局约 70 / 82 / 265 ms；AppKit 子树 23 / 121 / 421 个视图 | 已测到容量上限附近的 UI 构建成本；包含 NSPanel/NSHostingView 创建，不等于正式刘海开启动画耗时 |
| 全选调用与紧接的同步布局，1 / 50 / 200 项 | 约 2.3 / 7.6 / 29.4 ms | 只覆盖同步部分，不保证 SwiftUI 后续事务/实际屏幕呈现已经结束 |
| 模型层逐项移除 200 项 | 约 27–28 ms；200 次移除发布，另有一次整批加入发布 | 即使没有卡片渲染仍有批量 mutation 的优化收益；不是删除源文件 |
| 文件外部改名后访问 | 拖出所用缓存路径不存在；异步书签返回的新路径存在 | 已复现两种访问路径结果不一致；未执行真实外部拖拽 |

均为少量诊断样本，不计算 P95、不外推长期使用表现。布局截图仅含自建短文本素材，680×170 pt，可见约 4 张卡片；左侧 AirDrop 区域占用了显著空间。[查看测试面板](audit/2026-10-17-shelf-assessment/shelf-layout-fixture.png)

性能验收建议：接收确认 P95 < 100 ms，起拖主线程处理 P95 < 16 ms，正常本地 1/10/50 文件成功率分别记录；持续拖动/滚动按实际刷新率检查帧预算并单独记录 > 100 ms 停顿。它们是拟定门槛，不是当前已达标结果。Apple 指出离散操作约 100 ms 延迟会被察觉，而连续交互的主线程工作需要更短，通常应控制在约 5 ms 内。[Apple 响应性指导](https://developer.apple.com/documentation/xcode/improving-app-responsiveness)

## 4. 当前问题清单

### P1：优先影响核心操作成功率或明显响应

**A. 接收层存在“返回成功但没有接收”的路径。**

`ContentView.dragDetector` 的 onDrop 直接返回 true，不调用导入；只有刘海处于 closed 时才切换 Shelf。已打开 Home/Timer 等页面时，拖入不自动切页，若命中这层接收区域就不会存入内容。快速释放、页面切换和落在外围的实际命中情况还需真机验证。修复应统一真正的接收入口，或使仅探测区域明确拒绝 drop，不能假报成功。

复测：关闭状态快速放下；先打开 Home 再拖文件；落在内容区/边缘；取消拖拽。每次接受都必须可追踪到导入成功或可见失败。[代码](../DynamicIsland/ContentView.swift:1632)

**B. 一项慢来源阻塞整批显示，并阻塞后续批次。**

解析和队列串行，反馈在整批结束后才出现；单次 provider 等待可达 30 秒。多种表示的回退可能分别等待，不能把 30 秒称为整批上限。保留并发/存储预算，先加即时接收状态、逐项结果和取消/重试，再以 2–4 路有界解析评估收益。[导入队列](../DynamicIsland/components/Shelf/ViewModels/ShelfStateViewModel.swift:366)、[provider 等待](../DynamicIsland/extensions/NSItemProvider+LoadHelpers.swift:160)

**C. 拖出同步渲染未限制文本长度。**

正文允许 1 MiB，但卡片和拖拽预览把完整文本交给 SwiftUI，`lineLimit(2)` 不等于提前截断输入。使用短显示摘要，保留原文给复制/拖出；详情应另外展开。本轮渲染实测见证据目录。[预览](../DynamicIsland/components/Shelf/Views/DragPreviewView.swift:40)

同批处理大列表构建：200 项测试面板首次同步构建约 265 ms。不要直接把 HStack 换成 LazyHStack 就宣布解决；现有框选依赖实际挂载视图的 frame，虚拟化需要同时处理命中几何、跨屏外选取和自动滚动。可先将选择状态更新限制到受影响卡片，并用真实列表基准验证收益。

**D. 文件被外部改名/移动后，拖出可能拿到旧路径。**

拖出直接信任 cachedPath；可见卡片首次加载会异步纠正路径，但它不是持续监视，文件在加载后被外部移动，或立即多选拖出尚未刷新的项，仍可能输出过期 URL。先异步刷新访问状态；未就绪项给出提示，不在鼠标回调阻塞解析。Open/Copy 的异步解析与直接 Drag/Quick Look/Open With 的行为需要统一。[缓存访问](../DynamicIsland/components/Shelf/Models/ShelfItem.swift:200)、[卡片加载](../DynamicIsland/components/Shelf/ViewModels/ShelfItemViewModel.swift:66)

### P2：影响可发现性、可控性与长期使用

**E. 关闭 Shelf 后，数量 HUD 分支仍可能显示。** 两个分支检查非空和锁屏，没有检查 `dynamicShelf`；当前关闭开关保留项目，因此“隐藏但仍提示”的条件可以成立。统一所有显示分支对开关的判断。[独立 HUD](../DynamicIsland/ContentView.swift:1083)、[音乐副活动](../DynamicIsland/ContentView.swift:1395)

**F. 开启门槛大于部分功能所需。** 设置页要求 Documents 与 Downloads 都可读，或有 Full Disk Access，才允许从关闭变为开启。纯文字/链接、本来可访问的文件也被统一挡住。建议允许开启，再按具体来源提示访问问题；完整磁盘访问继续可选。[权限门槛](../DynamicIsland/components/Settings/SettingsView.swift:2624)

**G. 新内容追加在队尾，长列表缺少找回入口。** 200 项上限、横向单排、没有搜索/分组；源码未找到新增后的 scrollTo。新项可能落在当前可视区域之外。重复内容也只提示“已经存在”，不跳转该项。建议最近加入优先或滚到新增项；重复时定位并高亮已有项，保留稳定组内顺序。[添加](../DynamicIsland/components/Shelf/ViewModels/ShelfStateViewModel.swift:239)、[列表](../DynamicIsland/components/Shelf/Views/ShelfView.swift:206)

**H. 键盘流程不完整，清理缺少撤销。** Cmd+A 已有，Delete/Esc 放在框选视图的 keyDown；卡片点击没有明确把焦点交给它，因此键盘删除的可达性依赖焦点。未找到方向键、Space 预览、Cmd+C/V 的完整 Shelf 流程。批量删除逐项发布状态、安排保存和清理，应一次 mutation。移除后提供短时撤销比新增复杂分类更有价值。

**I. 文本多选后双击只留下最后一项。** 双击循环执行 open；对文字，open 的语义是清空剪贴板再写入，因此之前选中的文字会被下一项覆盖。应明确双击只操作当前卡片，或定义合并复制行为；本轮未触碰用户剪贴板。[双击](../DynamicIsland/components/Shelf/ViewModels/ShelfItemViewModel.swift:112)、[文本 open](../DynamicIsland/components/Shelf/Services/ShelfActionService.swift:49)

**J. 文档和入口文案存在偏差。** 中文 README 和生命周期文档前段仍写关闭会清空，后段与当前实现却是隐藏保留；空态只说“Drop files here”，没有说明文字、链接、多选和如何取出。这会影响用户信任和能力发现。[中文 README](../README.zh-TW.md:101)、[生命周期文档](shelf-lifecycle.md)

其他需注意的边界：普通文件不是副本，源文件被删除后不能靠 Shelf 恢复；拥有的临时副本受 100 MiB/项、250 MiB 总预算限制；拖出后 10 分钟保护期不代表浏览器长时间上传必然完成。文件表示必须在 provider 回调结束前复制，当前实现已遵守这一点，不能简单移到回调外异步复制。[Apple 文件表示文档](https://developer.apple.com/documentation/foundation/nsitemprovider/loadfilerepresentation(fortypeidentifier:completionhandler:))

## 5. 最值得培养的使用场景

| 优先级 | 触发与具体流程 | Shelf 的价值 | 优化重点 |
| --- | --- | --- | --- |
| 首要 | 从不同 Finder 目录收集 3–10 个文件 → 切到网页上传/邮件草稿 → 一起拖出 | 暂时卸下鼠标上的拖拽负担，省去反复切回源目录 | 一次收齐、明确数量、组拖出、失败保留 |
| 首要 | 截图/录屏素材 → 暂存 → 切到文档、编辑器或反馈页 → 挑选后递交 | 内容产生时有自然入口，跨窗口交接有明确终点 | 主动“加入 Shelf”动作、即时缩略图、Space 预览、用后清理 |
| 首要 | 下载完成 → 加入 Shelf → 检查版本 → 拖到目标应用 | 把已有下载完成提示变成下一步操作 | 复用下载完成事件，不新增常驻轮询；导入明确完成的文件 |
| 次要 | 两三个常用模板/品牌素材反复取用 | 高频复用，减少找目录 | 少量固定项，显示源文件可用性；固定临时副本前需设计持久存储 |
| 次要 | 浏览时收集少量链接/短段落 → 带到写作位置 | 当前任务的小篮子 | 一次性粘贴入口、标题摘要、合并复制；长文继续交给 Extra Space |
| 可选 | 选素材 → AirDrop 到自己的设备 | 跨设备交接 | 保留功能，把大区域是否常驻变为偏好；不默认把它当主任务 |

只有单个文件且源/目标窗口同时可见时，直接拖拽更短；不要为了“提高频次”强迫所有交接经过 Shelf。常驻的价值应是在跨窗口、跨目录、分步完成时显著省事。

## 6. 提升频次的最小方案

### 第一批：先让人敢用

统一 drop 接收与页面切换；即时出现接收数量/占位；慢项单独显示状态并可取消；限制拖拽预览标题；过期文件路径明确提示；修正关闭 HUD。维持默认复制、失败保留、不删除源文件。

成功信号：每个被接受的 drop 都得到最终结果；取消和失败不会丢引用；1/10/50 项矩阵中无静默丢项；起拖与交互延迟达到上文门槛。没有通过这批验收前，不扩大输入来源。

### 第二批：使核心操作更容易触发

增加可自定义的 Shelf 直达快捷键与打开后的 Cmd+V；补齐方向键、Space、Cmd+C、Delete/Esc。新项自动进入视野；显示已选数量和少量就近动作；空态直接演示“拖入 → 切应用 → 拖出”。保留既有原生暗色风格，缩小 AirDrop 所占空间，把暂存区作为主要目标。

成功信号：从其他应用能快速打开并加入当前剪贴板内容；重复落入时能找到已有项；不用右键也能完成选择、预览、复制、移除；移除可撤销。

### 第三批：连接高频事件，保持暂存架干净

先做下载完成“加入 Shelf”，再验证截图加入。默认按用户主动动作收集；自动收集作为可选项。随后提供最近优先、少量固定、按年龄建议清理；不默认定时删除未处理内容。

固定功能需要说明：固定源文件引用仍依赖源文件；固定临时副本若要跨清理长期可靠，应迁移到有预算的持久目录，而非仅加一个 pin 标志。空间/寿命承诺要一起设计。

暂缓云同步、完整剪贴板历史、AI 自动分类、大型文件管理器和全新视觉系统。这些能力提高复杂度，对当前最短交接链路的帮助有限。

## 7. 如何验证使用频次确实提高

先记录 3 个真实工作日基线，再用第一、二批方案试用 7 个工作日。没有埋点时用简单日记也可以，不必先建分析系统。

| 指标 | 定义 / 用途 |
| --- | --- |
| 有效交接次数/活跃工作日 | 收入后成功被目标应用接受，或完成一次复制/打开；区分动作类型，不用面板打开次数替代 |
| 适用任务选择率 | 实际适合中转的任务中，有多少自然选择 Shelf；需简短手工记录分母 |
| 接收反馈时间 / 起拖耗时 | P50、P95 与最慢样本；按本地文件、文本、附件来源分开 |
| 失败、取消、重复尝试 | 区分用户取消、provider 失败、目的地拒绝，避免把全部失败算作性能问题 |
| 项目停留时间与积压 | 是否出现一周不动的大量项目；多次使用与一次性交接分开看 |
| 体感与对照任务时间 | 每天只问“今天哪次比 Finder/直接粘贴省事，哪次更麻烦”；比较相同交接任务 |

建议试用目标：一周内覆盖至少 3 个工作日、自然完成至少两类核心场景，适用任务选择率提高且错误不增加。目标需随实际任务量调整，不凭空规定每天打开次数。拖拽的 `.copy/.move` 回调只代表接收方接受操作，不能统计为“远程上传完成”。如做计数，只需本地动作、耗时和结果，不采集文件名、正文或链接。

## 8. 仍需真实桌面验收

1. Finder → 关闭刘海 / 已展开其他页 / Shelf 边缘；快速释放与暂停后释放各测。
2. 1/10/50 本地文件；200 项已有内容下滚动、多选、框选和起拖。
3. 浏览器图片、系统截图缩略图、邮件附件、文本、链接；先在本地空白文档/草稿接收，不发送。
4. 拖出到 Finder 与本地网页 file input；取消、拒收、开启自动移除后的接受；确认源文件保持原位。
5. 外部重命名/移动、断开的外置盘/NAS、尚未下载的云文件、超限输入。
6. 多屏、全屏、隐藏刘海、锁屏/解锁、睡眠唤醒；关闭 Shelf 后残留 HUD。
7. Time Profiler / Hangs / Animation Hitches 实测，区分冷启动与热态；测试 10–30 分钟持续交接。长时间常驻能耗需要独立采样。

单元测试通过不等于这些用户流程已验收。本轮没有发现证据可直接宣称“所有拖拽无卡顿”或“增加某功能必然提升留存”。
